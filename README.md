# Infrastructure Provisioning

This file contains Terraform configuration to provision AWS infrastructure for the application (VPC, EC2 autoscaling, ALB, RDS PostgreSQL, monitoring and logging).


## Quick setup

Prerequisites:
- Terraform v1.5+ (consistent with provider lockfile)
- AWS credentials with permissions to create IAM, VPC, EC2, RDS, CloudWatch, S3 (for backend), DynamoDB (for locking), Secrets Manager
- `aws` CLI configured or environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`)

Initialize backend and bootstrap (only once):

```powershell
cd "Infrastructure Provisioning/terraform/bootstrap"
terraform init
terraform apply
```

This creates the S3 backend bucket and DynamoDB table used for remote state locking.

Deploy an environment (staging or production):

```powershell
cd "Infrastructure Provisioning/environments/staging"
terraform init -reconfigure
terraform apply
```

Replace `staging` with `production` for the production environment.

## Architecture decisions

- Modular layout: modules/{vpc,security-groups,alb,ec2,rds,monitoring} and environments/{staging,production} to keep environment-specific values separate from reusable logic.
- Per-AZ private route tables and NAT gateways to avoid duplicate route errors and to improve availability.
- EC2 launched via a `launch_template` + Auto Scaling Group for immutable, scalable instances.
- ALB fronting the EC2 fleet with target groups for HTTP traffic.
- RDS PostgreSQL in private subnets with a dedicated security group.
- Centralized monitoring using CloudWatch: agent installed on EC2 (via user_data), log groups (`/staging/*`, `/prod/*`) and dashboards for infrastructure and application metrics.

## Security considerations

- Secrets: DB credentials are generated by Terraform (`random_password`) and stored in AWS Secrets Manager. The Terraform configuration writes the secret; IAM roles should be granted least privilege to read the secret at runtime (for applications) via an instance profile.
- Networking: RDS is placed in private subnets; only necessary ingress rules are allowed (ALB -> app, app -> DB). SSH access is restricted by `allowed_ssh_cidr` variable.
- IAM: CloudWatch agent role uses `CloudWatchAgentServerPolicy`. Prefer scoping this role further in production.
- Terraform state: Backend S3 bucket should have encryption (SSE), restricted bucket policy, and versioning enabled. DynamoDB used for locking.

## Cost optimization measures

- Use small RDS instance classes for non-prod and right-size for prod; use `allocated_storage` conservative defaults.
- NAT gateways are per-AZ and can be expensive; consider using a single NAT gateway for low-cost environments or use NAT instances if appropriate.
- Use Auto Scaling with sensible min/max sizes to avoid overprovisioning.
- CloudWatch retention defaults are short (14 days) for non-prod; increase retention only where necessary.

## Secret management (implemented)

- For staging and production the configuration creates a `random_password` and stores credentials in AWS Secrets Manager (`aws_secretsmanager_secret` + `aws_secretsmanager_secret_version`).
- The generated password is passed into the RDS module to set the DB password. Applications should be updated to read the secret from Secrets Manager at runtime using an IAM role with minimal `secretsmanager:GetSecretValue` permission.

## Backup strategy (recommended)

- RDS: Automated backups are enabled via RDS (`backup_retention_period` set in the RDS module). For long-term backups, enable snapshot export to S3 or schedule `aws_db_snapshot` copies to another region.
- Logs: CloudWatch Logs can be exported to S3 or ingested into a central analysis cluster (OpenSearch). Configure subscription filters or export tasks for long-term retention.

## Next steps & operations

- Verify CloudWatch dashboards and log groups in the AWS Console.
- Grant the application EC2 instance profile permission to read the Secrets Manager secret.
- To destroy an environment:

```powershell
cd "Infrastructure Provisioning/environments/staging"
terraform destroy -auto-approve
```
